# 邮件投递骨架

> 起草者（主持人或邮件 agent）按本骨架为每家公司写一封。固定段落只替换占位符；定制段落每家公司重写，禁止群发感。
> 要素来源：实例 `log/email-queue.md` 的一行（公司、岗位、收件邮箱、附件命名格式、主题格式、正文要求、公告链接）。
> 发送受 `intent.permissions.email` 约束：审稿策略和每日上限见 `docs/redlines.md` §4。

## 0. 发送前核对（每封都做）

- [ ] **主题**逐字照公告要求的格式，例如“应聘岗位-姓名-学校-学历-届别”。公告没要求才用下方默认主题
- [ ] **附件文件名**逐字照公告要求，从 `materials/resume-cn.pdf` 复制一份改名后附加，原件不动
- [ ] 公告要求“正文粘贴简历”“不接受附件”“附件只能一个 PDF”等，照做
- [ ] 公告要求填写的额外信息（期望城市、到岗时间、信息来源等）从问题库取，写在正文里
- [ ] 收件邮箱与公告原文核对一遍，不从看板复制
- [ ] 同一收件邮箱同一岗位没发过（查 tracker）
- [ ] 外企按 `intent.policies.foreign_cv` 用对应语言的简历和正文
- [ ] **不写简历和问题库里没有的能力**：某个技术栈、某框架的熟练度，只要简历没写就不能说"熟悉/扎实/有经验"；不对口的岗位写"主栈是 X，Y 方向愿意在岗位上快速补齐"。发送前用关键词扫一遍（见 `docs/lessons.md`「邮件投递」一节）
- [ ] 真实经历以 profile 与问题库为准：简历和问题库里写过的技术栈才能说"熟悉"，拿不准就问用户，不默认拔高也不默认降格
- [ ] 公告格式本来不含姓名（如"应聘岗位 + 工作地点"）时照格式写，不要硬加姓名
- [ ] 公告给了多个收件邮箱（按城市、按岗位）时只发与所投岗位对应的那个或那组
- [ ] 公告要求原文以 `data/paperball/announcements.jsonl` 的 `from_url` 全文为准，候选名单里的摘录可能被截断

## 1. 默认主题（公告无要求时）

```
【应聘】{岗位名}-{姓名}-{最高学历学校}-{学历}-{届别}
```

## 2. 正文

```
{称呼：公告有 HR 名字写“{姓}老师您好”，否则写“招聘负责人您好”}：

【固定段 · 自我介绍】
我是{姓名}，{学校}{专业}{学历}，{届别}毕业生，{毕业时间}毕业。
从{公告来源，如“贵公司校招官网 / 公众号”}看到{岗位名}的招聘信息，特此投递。

【定制段 · 为什么是这家公司、这个岗位】
（每家重写，2–4 句。写法：
  1. 从公告或 JD 里挑一个具体点：业务方向、产品、技术栈、项目名
  2. 对应到自己的一段经历：做了什么、用了什么、结果是什么，只写 profile 和简历里有的
  3. 不写“贵公司是行业领军者”这类空话，不堆形容词）

【固定段 · 附件与联系方式】
附件为我的简历（{附件文件名}），{如公告要求其他材料，逐项列出}。
{公告要求的额外信息，逐行写：期望城市：…；到岗时间：…}
联系电话：{手机}，邮箱：{投递邮箱}。

感谢您抽出时间阅读，期待有机会进一步交流。

{姓名}
{日期 YYYY-MM-DD}
```

## 3. 定制段示例写法（结构示意，不要照抄内容）

- JD 写“负责 {某业务} 的 {某系统} 研发” → “我在 {某段实习/项目} 中负责 {相近模块}，用 {技术} 实现了 {可验证结果}，和岗位里 {某职责} 比较接近。”
- 产品岗 JD 写“负责 {某类产品} 的需求分析” → “我在 {某项目} 里做过 {用户调研/竞品分析/需求文档}，产出 {具体产物}，推动了 {具体变化}。”

## 4. 发送后

- tracker 标已投递，写发送时间和主题
- 你自己的看板（若有）标已投递，备注“邮件投递 {日期}”
- `log/email-queue.md` 该行状态改“已发送”
