# Moka

整理自该门户的实际使用（2026 年秋招季）。

> **填申请表先用 `skills/fill-moka`**（进到 `#/job/<uuid>/apply` 后跑一次，30–60 秒批量填好并出报告）。表单 DOM 结构、下拉/日历/地区弹层的坑都记在该 skill 的 SKILL.md「Moka 表单结构备忘」。

## 识别方式

- 域名 `app.mokahr.com`
- 校招 `/campus-recruitment/<租户>/<项目id>#/jobs`，社招 `/social-recruitment/...`，部分企业校招岗也挂在社招路径下
- 岗位详情 `#/job/<uuid>`，申请表 `#/job/<uuid>/apply`，成功页 `.../apply/thanks?...`
- 岗位卡片是 `<a href="#/job/{uuid}">`，直接取 href 跳转比点卡片可靠（相邻卡片容易误点）

## 注册登录

- 邮箱验证码登录，有邮箱入口
- **会话跨分站复用**：在一个 Moka 站登录后，其他企业分站进入时右上角已有头像，免登录
- 账号数据按企业分站存，但同一邮箱可以在各站直接验证码登录
- 部分企业站**免登录**：点“申请职位”直接进申请表，没有账号中心可查

## 投递流程

详情页“申请职位” → 申请表 → 上传简历（`input[type=file]`，name 常为 `resumeKey`）自动解析 → 补填 → 勾“本人已郑重承诺上述信息属实”等 → “预览并提交” → 预览确认页（只读卡片）→ 底部“返回修改 / 确认提交”

- “预览并提交”不是最终提交；“确认提交”才是
- **部分租户点“确认提交”会弹网易易盾滑块**：弹出后立即截图 handoff（kind=captcha），用户在浏览器里亲手拖（约 90 秒）；worker 等待时看页面是否落到成功页，不必等回复。滑块只能用户过，不要尝试脚本拖动
- 门户常写投递限额：“27届秋招允许投递 3 次”“允许 1 个月内投递 1 个职位”

## 必填坑

- **“申请职位”被浮层拦截**：详情页“分享”与“申请职位”相邻，容易误开分享弹层；右侧 `#latest_jobs` 浮层也会拦截点击。关弹层后坐标点击，或脚本直接 click
- 页尾有同名文案容器，按 `button` 过滤找真实按钮
- **“预览并提交”脚本 click 只触发滚动**，要滚动到可见后真实鼠标点击
- **重新上传简历会重新解析并覆盖你已改好的字段**（出生日期等会被改回解析值）：需要重传时，重传后把之前改过的字段全部再核一遍
- **删除解析条目或重传后，编辑区渲染不可靠**：以预览页展示的内容为最终事实，预览页不对就回去改
- **学校/专业下拉库里没有的名称**：下拉菜单底部的“添加全称”是菜单内一个独立输入框 + 添加按钮，在搜索框里打字不会带进去
- **家庭成员区块默认带一条空条目**：不填就点“删除本条”，否则校验卡住
- **textarea 用点击 + 逐字输入会插进已解析文本中间**：先全选删除再输入
- **文件槽容易错位**（照片进了简历槽）：按每个 file input 的 accept 属性分别定位简历与照片，上传后以预览页“附件简历”的文件名验收
- **自定义下拉**（年月、学历、城市）：语义定位不稳，滚动到可见 + 坐标点击 + 在可见 `[class*=option]` 中点选
- **出生日期年月控件**：月视图点年份标题进年代视图，首屏年代可能显示异常，点一次翻页后才出现真实年代，再连续翻到目标年代
- **学校联想**：会先联想出“某大学某学院”，要精确点学校本身；专业库无匹配时用“添加专业全称”自定义录入
- **多余块**：误点“添加”会产生空块，要删除；唯一的空工作经历块删除按钮隐藏且非必填时留空
- **checkbox**：label 文案在 wrapper 内，要点 input 本身或其 checker 父元素；有 svg 覆盖时坐标点击 input
- **元素引用漂移**：每次操作后重新取页面快照
- 获奖经历、当前薪资等无数据源时留空

## 附件限制

- 部分租户是纯在线简历表单，没有文件上传控件
- 有上传位的：简历 PDF 为必填，“上传附件”选填
- 预览确认页会显示附件简历文件名，可在此回读

## 提交后核验

- 成功页 URL 含 `/thanks`，显示“已成功提交申请，请静待佳音！”，URL 里带 candidateId 可作为回执（记在实例留痕里，不进仓库）
- 登录的租户：头像菜单 → “投递记录”（`#/candidateHome/applications`），状态如“申请成功”
- 免登录租户：只能靠 thanks 页和投递邮箱里的确认信

## 提交阶段滑块与投递次数限制（2026-09-17）

- 「确认提交」之后弹出的易盾滑块：**拖过即完成提交**。用户处理完后 worker 必须回读「我的投递」确认，不能当作"还没提交"去重填
- 部分租户限制投递次数（如每人限投 1 个职位，或 3 个月内限 1 岗）。弹「已达到投递限制」说明这个账号此前已经投过，去投递记录核对，不要换岗位重试
- 需要用户确认的公司：填完停在预览页，**不点「确认提交」**（点了就会弹滑块，拖过即提交）
