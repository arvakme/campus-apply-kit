# 飞书招聘（Feishu ATS）

整理自该门户的实际使用（2026 年秋招季）。

## 识别方式

- 域名 `<租户>.jobs.feishu.cn`，或企业自有域名下同样的路径（如 `campus.<企业>.com`）
- 岗位详情 `/campus/position/<id>/detail`，申请表 `/campus/resume/<id>/apply`，成功页 `/campus/resume/applied`，应聘记录 `/campus/position/application`
- 登录页 `/campus/login` 或 `/campus_recruitment/login`
- 组件：`atsx-select`、`ud__select`、formily 表单

## 注册登录

- **+86 手机验证码登录**（未注册自动建号），或抖音/第三方扫码
- **没有邮箱入口** → 一律 handoff（kind=sms_code）
- 同一租户登录后直接回到申请表

## 投递流程

详情页“投递” → 登录墙 → 申请表：推荐方式（默认“无”）→ 意向城市（常随岗位固定为只读文本）→ 附件简历上传解析 → 基本信息 → 教育 → 实习/项目 → 语言 → 自我评价 → **“提交简历”**

- **没有预览页，“提交简历”就是最终提交**。user 档的单停在这个按钮前
- 招聘项目常有限额：“官网 + 内推合计最多投 3 次”“项目限投 2 岗”

## 必填坑

- **“添加”按钮语义**：节头“添加”打开第一个表单；表单下方的“添加”是再开一个新空白块，不是保存。已填数据自动保留。每节只点一次节头“添加”，多出来的空白块用块头图标按钮删除，否则空白块的必填项会拦提交
- **下拉被遮罩**：性别、渠道、语言、平台类下拉的 input 被 div 拦截，普通点击超时 → 按元素中心坐标派发 mousedown/mouseup/click
- **下拉值回读**：`input.value` 恒为空，真实值在 `.ud__select__selector__selectItem` 的文本里
- **长列表下拉**（国籍）：下拉内有搜索框，输入过滤后点精确项
- **label 定位**：表格布局，从 label 向上找父节点会命中相邻字段（出现过把国籍填进姓名框）。按 DOM 顺序取 label 之后第一个可见控件
- **年月选择器**：`.ud__picker-panel-header-btn` 打开年份面板，默认显示当年，选历史年份先开年面板
- **没有“至今”**：进行中的经历结束时间选当前月，在留痕注明
- **三级树形地点级联**（中国大陆 ▸ 省 ▸ 市）：输入城市名筛选后必须点叶子节点文字，点中间层只提交到该层
- **“解析并覆盖”** 按钮坐标点击不生效，脚本 click 可以
- 必填“获取职位信息的渠道”常见选项“校招官网/微信公众号”
- 学历类型、成绩排名等选项里可能没有精确档位，按问题库规则降档

## 附件限制

- 通常一个附件简历上传位，直接对唯一的 `input[type=file]` 上传，无文件选择器弹窗
- 上传后显示“上次上传 <时间>”，刷新回读确认
- 一般无强制照片、成绩单

## 提交后核验

- 成功页 `/resume/applied`：“简历已收到，本职位将成为你的第 1 志愿”
- 右上角手机号菜单 → “查看应聘记录”：岗位、第 N 志愿、官网投递、城市、投递日期
- 状态流转：投递简历 → 评估 → 面试


## 登录滑块死循环（2026-09-17）

飞书招聘手机号登录：点「获取验证码」先弹拼图滑块，**用户拖过后短信已自动发出**。worker 若再点「获取验证码」或「刷新拼图」，就会弹出新滑块，用户陷入反复拖滑块的循环。正确做法：用户过滑块后只用 `host/sms-code.py --sender-hint 飞书 --wait 120` 取码登录；验证码一律不许 worker 自行刷新。

**现行做法**：登录整段交给用户——worker 只填手机号、勾隐私协议，发 `--kind login` 关卡交出空间；用户完成滑块、短信码、登录后点 Return to agent，worker 再接着投。
