# 北森（Beisen Phoenix）

整理自多家北森校招门户企业租户的实际使用（2026 年秋招季）。

**耗时参考**：顺利时一家 10–25 分钟；最大耗时项是 GeeTest 点选（每家通常 2 次，都要人来过）。

## 识别方式

- 域名 `<租户>.zhiye.com`，或企业自有域名（如 `career.<企业>.com.cn`）下同样的路径结构
- 路径：岗位列表 `/campus/jobs`，岗位详情 `/campus/detail?jobAdId=...`，申请表 `/form?fromPage=job&jobAdId=...`，投递记录 `/personal/deliveryRecord`
- 页面组件 class 前缀 `phoenix-`（`phoenix-radio`、`phoenix-select`、`phoenix-checkbox`）
- 部分租户岗位详情不跳页，是列表卡片内嵌展开，点卡片标题即展开，“查看详情”不跳转
- 同厂商不同租户账号**不通用**，每个企业站要单独登录

## 注册登录

1. 点“立即投递”跳 `/login?goto=...`，常见只有“微信扫码登录/注册”一种入口 → handoff（kind=wechat_qr）
2. 扫码后落 `/login/bindMobile`，要求绑定手机号或邮箱完成注册
   - 选“绑定邮箱”页签，填投递邮箱
   - 点“获取验证码”会先弹 **GeeTest 点选验证码**，遮罩盖住按钮，表现为“点击无反应”或“尝试过多，请点击此处重试” → handoff（kind=captcha）
   - 用户过码后邮件验证码可以用 himalaya 自取，有效期约 10 分钟
   - 用户也可以直接绑手机号收短信
3. `/login/setPwd` 设置密码页可以点“跳过”
   - **一家通常要人工过 2 次 GeeTest 点选**：绑定邮箱获取验证码时一次、预览页“确认投递”时再一次；加上扫码登录，一家最多 3 次 handoff。派单时预期好，关卡队列按公司集中推送，别让用户来回切
4. 登录后先去 `/personal/deliveryRecord` 查有无历史投递

## 投递流程

岗位详情“立即投递” → `/form` 申请表（顶部提示“最多可投 N 个校招职位，还可投 M 个”，M 等于 N 说明没投过）→ 顶部“上传简历”解析 → 逐项修正补填 → “暂存” → “预览并提交” → 预览页 → 勾“我已阅读并同意《北森隐私政策》” → “确认投递”

- “预览并提交”进入预览页，还不是最终提交；最终提交是预览页的“确认投递”
- **关卡 resolved ≠ 投递完成**：某租户用户过了两次点选后，投递记录仍停在“暂存”，第 3 次才真正提交。核验只信 `/personal/deliveryRecord` 里“已完成的投递”，不信暂存、不信 handoff 状态
- **点“确认投递”会再弹一次 GeeTest 点选**：弹出后立即截图 handoff（kind=captcha），用户过码后按钮才真正提交；等待期间按关卡协议同时看页面，页面落到成功提示/投递记录就继续
- 投递后可以在投递记录里点“编辑”修改（`isEdit` 表单），改完同样走预览 → 确认投递，是更新同一条记录，不算重投。编辑态没有“暂存”

## 必填坑

- **长文本和部分输入框不认程序赋值**：DOM 值变了，暂存后回滚。统一用真实点击聚焦 + 全选删除 + 键盘输入，再暂存
- **年龄等字段**：程序注入不被 React 注册，键盘真实输入
- **radio/checkbox**：`input.checked` 不可信，看 `phoenix-radio--checked` 类；“至今”勾选要点左侧勾选框本体，点文字只翻 input 不同步状态（表现为视觉不勾、结束时间不禁用）
- **弹层控件**（月份选择器、城市树、职业树）：鼠标坐标点击最稳。民族、地区类是“勾 radio 图标 + 点确定”模式
- **城市多选**：搜索框逐城搜索再勾结果行；只搜城市名可能先出“××国家级产业基地”这类非市级项，要带上“市”字搜；“全国”与具体城市可以共存，要手动删
- **意向工作地点不回显**：选好后暂存载荷里有值，刷新后编辑态显示“请选择”，进预览前若显示空会被校验拦，每次进预览前重选一次
- **强制行**：在校实践、在校职务、获奖情况等区块有空行且没有删除按钮，表单强制至少各填一条。无数据时 blocked，不编
- **技能区解析垃圾**：可能生成几十行，要逐行删除（滚动到可见后坐标点击，`el.click()` 不触发）
- **本科成绩（GPA）** 等字段可能为必填自由文本
- **程序赋值（native setter + input 事件）不进 React state**：期望月薪、项目名、职务、描述都出现过暂存后丢值，只能真实键盘输入；checkbox 的 `.checked` 与视觉不一致，以截图为准
- **“现月薪/目前薪资”可能必填**：在读学生填 0（事实性回答，见问题库 current-salary 口径）
- **部分租户注册密码只允许字母和数字**：统一密码含特殊字符会被拒，可点“跳过”不设密码，之后该分站继续用扫码 + 绑邮箱登录
- **下拉框（phoenix-select）单击只聚焦不展开**：要真实鼠标点右侧箭头，或聚焦后按 ArrowDown 才出选项；可搜索的下拉用键盘输入关键字再回车。不要用 evaluate 直接赋值，界面会显示但暂存不落库
- **树形面板复选框**（职业树、城市树）：必须点每行左侧的小方框本体，点文字只高亮不勾选，表现为顶部“已选 0/1”不变
- **误点会让整张表状态丢失**（某次点错弹层后所有已填项清空）：重新“上传简历”触发解析即可恢复大部分字段，再逐项补；所以**每填完一个区块就暂存一次**
- **“期望从事职业”是 radio 列表**：行高小、文字和圆点对不齐，按行的坐标精确点击圆点；选值按问题库规则 `expected-occupation`（测试岗选软件测试类、开发岗选软件工程师类、AI/Agent 岗优先人工智能/算法工程类里的应用开发项）
- 日级日历：年选择 → 年网格 → 落到某月日视图 → 上一月/下一月逐月调 → 过滤当月日期格点击（截图坐标会漂移）
- 教育经历有的租户没有起止时间字段，只有学校/专业/学历
- **刷新前必须暂存**：否则意向地点和新填的行全部丢失

## 附件限制

- 简历：顶部上传位解析后同时挂到“简历附件”字段；也有租户上传的 PDF 只用于一次性解析，编辑/打印视图不展示附件名，无法回读文件名，在留痕里如实记录
- 证件照：图片 input，上传成功会发 `POST /api/v2/Data/File?fieldName=IDPhoto` 并返回持久路径；路径写错时组件仍回显文件名但不发请求
- 刷新回读显示“重新上传 / <文件名>”才算持久
- **页面有多个隐藏的文件上传框**（简历、证件照、附件）：按 DOM 顺序第一个通常是顶部“上传简历”，上传前先确认它所在区块标题，再传文件
- **解析会错位**：出生日期被解成错误年份、项目名被解成简历里的网址、描述串段，上传后逐字段对照简历修
- **简历解析质量因租户而异**：有的租户能解析出实习经历，有的整块“工作/实习经历”为空需要全部手填；解析后逐区块对照简历

## 提交后核验

- `/personal/deliveryRecord`：“已完成的投递(N)”列表，含岗位名、进度（如“HR筛选-未处理”“简历入库-HR简历初筛中”）和投递时间
- 投递记录里“查看/打印”（`/form?fromPage=printResume&id=...`）可以回读全部落库字段
