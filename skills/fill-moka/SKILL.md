# fill-moka

填 Moka 申请表最花时间的不是点鼠标，是**逐个字段判断"这一栏该填什么"**再一个个点下拉。这个 skill 把两件事都批量化：一次请求判完整页字段，能从问题库取到答案的直接写进去并回读校验，判不准的、需要你拿主意的列出来交给你。

实测（2026-09-18，均从空白页开始、不提交）：

| 表单 | 字段 | 脚本写入 | 解析带入并核对 | 留给 worker | 耗时 | 花费 |
|---|---|---|---|---|---|---|
| 某软件公司·开发岗（简表） | 17 | 9 | 4 | 2（1 个本就该空） | 31 秒 | $0.0004 |
| 某制造业集团·开发岗（长表） | 83 | 19 | 17 | 4 + 分段经历 37 | 63 秒 | $0.0007 |

浏览器层仍然是 ego（登录态、关卡交接都在那里）。**skill 不提交、不碰验证码、不编造值**——这些仍归你。

## 什么时候用

- 投 `app.mokahr.com` 的公司：登录完、选好岗位、**进到职位申请页**（地址形如 `…#/job/<职位id>/apply`）之后
- 续投：页面丢了要重填整表
- 不适用：飞书、北森、公司自建门户（表单结构不同，照常手填）

## 怎么用

```bash
bash $CAMPUS_REPO/skills/fill-moka/scripts/run.sh \
  --space campus-slot-3 \
  --url "https://app.mokahr.com/campus-recruitment/<tenant>/<id>#/job/<jobId>/apply" \
  --instance $CAMPUS_INSTANCE \
  [--page p2] [--dry-run]
```

- `--space`：你自己的 ego 空间名。空间必须在 agent 手里；用户接管中会直接报错退出，等 Return to agent 后再跑
- `--url`：**职位申请页**，不是职位列表页。脚本会在空间里找已经打开这个职位的标签页直接用（不会重新加载冲掉你已填的内容）；找不到才在 p1 打开。想指定标签用 `--page`
- `--dry-run`：只抓字段和映射，不往表单里写
- 可以重复跑：已有值的字段只核对、不覆盖

## 报告怎么读

stdout 是一段 JSON。各段含义与你要做的事：

| 段 | 含义 | 你要做什么 |
|---|---|---|
| `已填明细` | 脚本写入且**回读一致**的字段（证件号、手机等敏感值显示为〈已掩码〉） | 不用管。`籍贯` 这类地区字段带"请回读核对层级"提示时看一眼省/市/区是否选全 |
| `解析已带入且已核对` | 简历解析带进来、和问题库一致的字段数 | 不用管 |
| `解析值与问题库不一致` | 页面已有值和问题库对不上——Moka 简历解析**经常把出生日期、就读时间搞错** | **以问题库为准改掉**（脚本不覆盖已有值，怕冲掉你手改的内容） |
| `待处理明细` | 判不准（置信度 < 0.8）、问题库没有、答案是规则要你判断、控件脚本不会操作 | 逐条处理；`hint` 是问题库原文。能复用的答案用 `host/qb.py add` 补库 |
| `分段经历` | 实习/项目/获奖/语言/家庭成员等可重复分组，按"分组·第几行"列出空着的字段（带 * 必填） | 对照简历核对解析结果、补空。**脚本不碰这些**：问题库是扁平的，分不清"第几段经历" |
| `提醒` | 如"教育经历里没有本科那一行，需要点『添加』" | 照做 |
| `未处理的控件` | 上传、勾选框 | 附件按问题库指定的文件传；承诺书勾选由你判断 |

之后照常：提交权限按工单（名企停在提交前发 `submit_confirm`）、提交后回读、`events.py outcome` + `registry.py add` + JD 存档。

## 脚本怎么判断（知道这些才知道怎么让它填得更多）

1. **字段名和问题库某条的问题/别名一字不差 → 直接命中**，不问模型。所以某个字段反复进"待处理"时，最有效的办法是补别名：`uv run host/qb.py alias <条目id> --add "字段名"`。同一别名只能属于一个条目（命令会拦），否则两条都不命中
2. 其余字段批量问 Jev：先判属于哪一类，再在该类里选条目。置信度 < 0.8 一律不填——填错一个字段（期望薪资被推成别的数）比留空更难发现。阈值在 `skills/fill-moka/scripts/map-fields.mjs` 的 `MIN_CONFIDENCE`
3. **教育经历按行认阶段**：看这一行的学校/学历是硕士还是本科，只在该阶段的条目里找（条目 id 或问题里带 `master`/`bachelor`/硕士/本科 即归该阶段）。"是否最高学历/是否第一学历"由阶段直接推出。认不出阶段的行整行交还给你
4. 下拉：先拿问题库答案和选项做字面匹配；规则条目里的优先级链（形如 `城市A>城市B>城市C`）按顺序挑第一个存在的选项；都不行再问 Jev，仍不确定就交还
5. 规则类条目（渠道、到岗时间、专业排名）按设计交还给你，不自动填

## 依赖与降级

- **ego-browser**：必须
- **Jev（Vercel AI Gateway）**：钥匙串 `campus-apply-vercel-gateway`。取不到 key 或调用失败时 `映射降级=true`，只输出字段清单，你照常手填，不阻塞投递。Node 依赖首次运行自动装到 `~/.cache/campus-apply/node`
- **问题库**：`$CAMPUS_INSTANCE/question-bank.yaml`；简历取 `materials/resume-cn.pdf`

## Moka 表单结构备忘（改脚本前先看）

class 都带构建哈希，只能按前缀匹配。

- 分组 `apply-block-*` > 标题 `blockTitle-*`（带"添加"= 可重复）> 每段一个 `apply-fields-*`（可重复的带 `multi`）> 字段 `apply-field-*` + 类型 class（`string_info`/`select_info`/`bool_info`/`date_info`/`day_info`/`location_info`/`text_info`/`multi_select_info`/`confirm_info`）
- 下拉弹层挂在 body 末尾 `sd-Dropdown-dropdown-*`，选项 `sd-Menu-container-*`。**点一下展开，再点一下收起**；页面是平滑滚动，滚动途中取坐标会点空——取坐标前要等位置稳定（`lib.mjs` 的 `stablePos`）
- **下拉/日期只在失焦时重新校验**：脚本选完最后一个下拉后没人让它失焦，旧的「必填项未填写」会一直挂着（值其实已写入）。所以每次写完都点一下该字段的标题让它失焦，再回读报错（`lib.mjs` 的 `settle`）；仍报错的记为失败交还 worker
- 年/月下拉有 200 个年份，选项要先滚到可见再点；选过值的下拉 placeholder 为空
- `day_info` 是日历弹层：`«‹ 2026年 九月 ›»` + 日期格；有的只到"年月"精度，点完月份就结束
- 地区弹层（省份/城市/县区标签页，选项是 `sd-Tag-*`）**不认 Escape**，要点到外面才收；不收会挡住下一个下拉
- 手机号 = 区号下拉 + 号码输入框，证件号 = 证件类型下拉 + 号码输入框：取"不在 `sd-Select-container` 里的那个 input"
- 简历控件 `input[name="resumeKey"]`（另一个 file input 是照片）；上传后等解析回填再抓字段
- ego 的 `page.evaluate` 只接受一个参数；`ego-browser nodejs` 不继承环境变量、只吃单文件（所以 `run.sh` 用占位符传参、把 `lib.mjs` 拼在脚本前面）
