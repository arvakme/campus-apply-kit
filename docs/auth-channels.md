# 登录与验证通道策略

> 默认的自动化优先级：人工介入尽量少，99% 情况自动化。
> 本文是 worker 撞登录/注册/验证墙时的判定依据。配套文件：
> `docs/platform-accounts.md`（预注册清单）、`docs/contracts.md` §8.6/§8.7（人工关卡时效与兜底）、
> `docs/redlines.md` §2（不可逾越的环节）、`portals/`（单门户细节）。

## 1. 四级通道与判定顺序

原则：能用上游通道就不用下游；下游通道（短信码自取失败、扫码）才消耗用户时间。

```
撞登录/注册墙
  │
  ├─ L1 平台预登录 ───────────────────────────────────────────────
  │    accounts.md 命中该平台 → 该站登录态已在 ego lite profile 里就直接进；
  │    登录态掉了按平台默认通道恢复（见 §3 表）
  │    ↓ 无记录 / 恢复失败
  ├─ L2 邮箱通道 ─────────────────────────────────────────────────
  │    门户有「邮箱注册 / 邮箱验证码登录」入口？
  │      是 → 邮箱走通；验证码用 himalaya 自取（不发信、只读收件箱）
  │      发码前撞图形码 → 走「图形码支线」（见下），过码后继续自取
  │      邮箱码 TTL 太短（实测 ≲3 分钟，取码+填写往返两次仍超时）
  │        → 降级 L3（门户同时支持手机码时）或 handoff kind=sms_code 用户手输
  │    ↓ 无邮箱入口
  ├─ L3 手机短信通道 ─────────────────────────────────────────────
  │    门户有「手机号 + 短信验证码」入口？
  │      是 → 填本人手机号发码 →
  │        uv run $CAMPUS_REPO/host/sms-code.py --since 5m \
  │          --sender-hint <公司或平台名> --wait 90
  │      取到码 → 填入继续；退出码 2/3/4（超时、无库、无完全磁盘访问权限）
  │        → handoff kind=sms_code，等用户在 §8.6 会话里回码或手输
  │    ↓ 无手机码入口
  └─ L4 扫码通道 ─────────────────────────────────────────────────
       只剩微信/抖音/App 扫码 → 截二维码 → notify.py handoff kind=wechat_qr
       （§8.6 时效协议：≤5s 到手机、过期自动刷新、chain 接力）
       人脸 / 实名核验 / 付费 / 电子签 → 直接 blocked，不接力
```

图形码支线（任何一级的发码/登录/提交按钮前都可能弹出）：

```
图形验证码 / 滑块 / 点选 / 旋转
  → 截图 log/shots/captcha-<id>-<n>.png → team-msg 验证码特种兵
    （常驻 codex pane；它回单行 JSON 指令，worker 执行）
  → 连续失败 3 次 → handoff kind=captcha（夜间按 gate_policy 挂起）
  纯字符识别码 worker 可自行 OCR，不必发特种兵；
  可选付费打码服务留作配置项（默认关闭，仓库不内置任何服务商账号）
```

## 2. 各级触发条件 / 超时 / 失败降级

| 级 | 触发条件 | 典型超时 | 失败降级 |
|---|---|---|---|
| L1 预登录 | `accounts.md` 有该平台记录；ego lite profile 登录态存活 | 打开门户右上角显示头像/账号即通过 | 按平台默认通道恢复登录；恢复不了降级到该平台的 L2–L4 |
| L2 邮箱码 | 门户提供邮箱注册或邮箱验证码登录 | himalaya 轮询收件箱；建议等 ≤120s | 码 TTL ≲3min 两次往返仍超时 → L3 或 handoff；发码被图形码拦截 → 图形码支线 |
| L3 短信码 | 门户提供手机码登录/注册；iPhone 短信转发到本机已开 | `sms-code.py --wait 90`（每 2s 轮询） | 退出码非 0 → handoff `kind=sms_code`；转发没开 → setup-checklist §3 引导用户开 |
| L4 扫码 | 门户只剩扫码入口（或前三条全不可用） | 二维码有效期按页面（wechat_qr 默认 120s） | §8.7 兜底矩阵：自动刷新 ≤3 次 → parked 释放 worker → 用户方便时再扫 |
| 图形码 | 发码/登录/提交前弹滑块、点选、旋转、字符图 | 特种兵单轮回指令超时按现场定 | 连败 3 次 → handoff `kind=captcha` |
| 人脸/实名/付费/电子签 | 页面识别 | — | blocked，不接力（红线 §2） |

## 4. 验证码 TTL 经验值

实测过的写实测值；没有的一律"待实测"，worker 实测后补回本表。

| 门户/平台 | 码型 | TTL |
|---|---|---|
| 北森（绑邮箱环节） | 邮件码 | ≈10 分钟，himalaya 自取可行 |
| 某银行系科技子公司（自建） | 邮箱码 | ≈60s，取码到登录须 <40s → 自取来不及，走用户手输 |
| 某股份制银行（自建） | 邮箱码 | ≈2 分钟 → 用户手输路径 |
| Moka | 邮箱码 | 待实测 |
| 飞书招聘 | 短信码 | 待实测 |
| 智联 | 短信码 | 待实测 |
| 各银行/国企自建 | 短信码 | 待实测 |

经验阈值：邮箱码 TTL ≥5 分钟自取稳；1–3 分钟看手速（取码+填写+提交一次往返内完成才算成功）；≤1 分钟基本只能用户手输。短信码由 sms-code.py 本机轮询（2s 间隔），TTL ≥1 分钟即可自取。

## 5. 表单类投递说明

问卷星 / 腾讯文档 / 钉钉表单 / 金数据等表单类入口**通常不需要登录**：打开链接直接填表，按 sop §4 执行。例外待实测：腾讯文档可能要求微信/QQ 登录态（ego lite profile 里若有则直接用，没有按 L4 handoff）。表单提交后没有"我的投递"可回读，以成功页截图 + 提交时间留痕为准。
