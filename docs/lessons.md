# 流水线错题本

> 门户相关的坑写进 `portals/<门户>.md`；问题库缺口进问题库；**本文件只收流程、工具、看板、协作层面的问题**。
> 每条写清：现象 → 根因 → 改在哪。你自己踩到的新坑接着往下写（AGENTS.md §9）。
> 下面是框架作者在一轮真实秋招（数百家公司）里踩出来的，已经去掉了具体公司和个人信息。

## 人工关卡（扫码 / 验证码 / 终审）

| 现象 | 根因 | 改在哪 |
|---|---|---|
| 用户已经扫码，看板「待我处理」一直挂着 | 连续两道关卡时 worker 只 resolve 了后一个 | 关卡通过即 resolve；`handoff-sweep.py` 每分钟按后续事件自动收尾 |
| 用户在浏览器里亲手过了验证，worker 还在空等聊天回复 | 等待循环只看回复不看页面 | 等待以**页面**为准 |
| 一口气收到十几个验证码，用户处理不过来，过期的还在推 | 每个 worker 各推各的 | 关卡排队：同时最多 N 个在手机上（`gate_queue.max_active`），两段式推送——轮到时 worker 先回页面确认验证码还在、重新截图，再推 |
| 推送说"去空间 X 处理"，打开发现是另一家公司的页面 | worker 在一个浏览器空间里开了很多标签，交出的不是关卡那一页 | 宿主机在推送前硬校验：空间名对得上、只留关卡页、再 handOff；校验不过不推 |
| 同一个确认请求被推了 3 次 | 超时太短 + 无限重推 | 终审/登录类 45 分钟超时；同一关卡最多重推 1 次 |
| 用户说"去吃饭"，手机仍不断响 | 只让 worker 不等待，没关推送 | 勿扰模式：期间通知只入队，结束后补发 |
| 想让 AI 直接把点选/滑块点了 | — | **不做**：自动绕过人机验证既违规也容易封号，保持用户亲手处理 |

## 浏览器控制权

| 现象 | 根因 | 改在哪 |
|---|---|---|
| 用户点了「交还给 Agent」，agent 仍一直报"控制权失败" | `handOff()` 后必须用 `takeOverTaskSpace(空间 id)` 重新接管，旧 task 对象失效 | AGENTS.md「浏览器控制权交接」 |
| agent 卡在控制权失败里转圈 15 分钟，token 烧完 | 无限重试；而且用了按 token 计费的模型驱动浏览器 | 最多重试 2 次然后 `waitForControl`；填表 worker 用不按 token 计费的 agent |
| 浏览器空间越开越多，电脑卡死 | 每家公司新建一个空间、不回收 | 固定 N 个槽位空间（`slot-pool.py`），一家做完清空标签接下一家 |

## 派单与并发

| 现象 | 根因 | 改在哪 |
|---|---|---|
| 中途发给 worker 的新规则全部没生效 | agent 执行长命令时消息只排队 | 每轮命令 ≤2–3 分钟；**规则写进工单模板和 `state/worker-rules.md`，不靠中途喊话** |
| 并发开到 10，所有 worker 同时卡住 | 触发模型限流，没人回页面释放关卡队列 | slot-pool 识别限流提示自动叫醒，每 30 秒最多叫一个；短时间叫醒多次就暂停派新单 |
| 同一招聘门户并发投两家子公司，第二家被"已应聘其它岗位"拦住 | 有些集团门户一个账号同时只能挂一个申请 | 同门户同账号不并发；写进该门户 playbook |
| 回执一律 `scope=violated`、被降成 failed，实际都投上了 | 共享实例目录 + 每小时自动快照，让"派单时/交活时脏文件对比"必然误报 | 投递池派单不传 `--scope`；统计和日志一律以 `state/outcomes/<id>.json` 为准 |
| 超时清理把正在等用户确认的任务杀了 | 超时不区分"在干活"和"在等人" | 有未处理关卡时超时放宽 |
| 批量清理进程时把所有 worker 都杀了 | macOS 的 `ps` 不支持 `etimes`，过滤条件失效，xargs kill 了全部 | 不用批量匹配杀进程；只关任务已回执、且不在投递池里的 |

## 记账

| 现象 | 根因 | 改在哪 |
|---|---|---|
| 查岗后跳过的公司没有任何记录，下次又派一遍 | 模板只要求提交成功写结果 | 跳过、卡住也必须写 outcome |
| 门户上已经投了，台账里没有，后来差点重投 | 提交阶段的滑块一拖过就算提交了，worker 没回读 | 任何"确认提交"后的验证通过，必须回读门户投递记录；重填前先看「我的投递」 |
| 汇报的投递数比实际少 | 只数了主动回报的 worker | 一律按 outcomes 统计 |
| 定时任务找的文件名和生成的文件名差一个连字符，当天任务静默没跑 | 两处各自拼文件名 | 文件名只在一处生成；定时任务失败要有通知 |

## 邮件投递

| 现象 | 根因 | 改在哪 |
|---|---|---|
| 二十多封邮件写了简历上没有的能力 | 起草 agent 为贴合岗位自行发挥 | 发送前用关键词扫描"熟悉/精通/扎实 × 技术名词"；拿不准的经历**问用户**，不默认拔高也不默认降格 |
| 一个 worker 写 90 封，十几分钟没落盘 | 先整体规划再动手 | 拆成几个 worker 按名单分段，要求"先落盘第一封" |
| 担心进垃圾箱 | — | 自有域名 + DKIM/SPF；每封间隔 45 秒 ±1/3 抖动；每日上限；逐家定制主题正文；`sent.json` 幂等防重发 |

## 看板与同步

| 现象 | 根因 | 改在哪 |
|---|---|---|
| 看板看不到今天的投递 | 只读手写台账 | 看板合并事件流、投递结果、防重投登记 |
| 两小时没动静的任务还显示"在跑" | 没有活跃度判断 | 2 小时无事件标"搁置" |
| 改了本地配置想上排行榜，一直不生效 | 上榜开关只在配对那一刻写进 relay | 每次上报带上本地开关，relay 据此更新 |
| 朋友的机器一直拿不到修复 | 本地有自己的提交导致分叉；agent 不读 templates/ | 使用者的仓库只 pull 不 commit；关键规则写进 AGENTS.md（agent 自动加载的唯一入口） |

## 批量填表（skills/fill-moka）

| 现象 | 根因 | 改在哪 |
|---|---|---|
| 下拉时开时不开 | 页面平滑滚动，滚动途中取的坐标点下去落空；已展开的下拉再点会收起 | `lib.mjs`：等坐标稳定再点；先收干净再展开 |
| 选上了值，表单仍报"必填项未填写" | 下拉只在失焦时重新校验，最后操作的控件没人让它失焦 | 每次写完点一下字段标题让它失焦，再回读报错；回读要同时看"值"和"报错" |
| 教育经历里本科那一行的学位被选成了硕士 | 问题库是扁平的，表单是多行的 | 教育经历先认出这一行是哪个阶段再选条目；其它分段经历脚本不碰，只汇总给 worker |
| 简历解析把出生年月解析错了，人工很难注意到 | 解析结果没人核对 | 已有值逐项和问题库比对，不一致的单列报告 |
